## Цель (что хотел пользователь)

На экранах результатов Streamlit («Найти страну» и «Понять своё место»):

1. Кнопка **«Скачать изображение для соцсетей»**.
2. По клику файл падает в «Загрузки», пользователь **остаётся на том же экране** с графиками (не новая страница, не пустой экран).
3. Картинка **квадратная**, как рекламный референс (вертикальная иерархия: заголовок → крупный результат → блок диаграмма+QR → текст → URL).
4. **Прозрачный фон**.
5. Тексты — из `data/dialog_messages.json`, максимально переиспользовать существующие ключи.
6. Логирование: событие `load_image`, параметр `type` = `country` | `place`.

### Макет «Найти страну»

| Зона | Содержание |
|------|------------|
| Заголовок | «Бот для расчёта индексов ценностей Инглхарта-Вельцеля» (`share_image_title`) |
| Крупно | Краткий результат RV/SV (`share_image_result`) |
| Слева | Scatter стран (тот же смысл, что на экране) |
| Справа | QR на лендинг + CTA «пройти» (`share_image_qr_cta`) |
| Ниже | Информация о стране обычным шрифтом (`country_profile_card` / `find_country_result`) |
| Низ | URL + призыв пройти самому (`share_image_footer_url`, `share_image_footer_cta`) |

### Макет «Понять своё место»

Аналогично, но:

- вместо scatter — **две гистограммы** с этой страницы (`own_place_charts` в meta);
- вместо профиля страны — текст **насколько пользователь отличается от выборки** (`share_body_lines` в meta, из тех же `find_own_place_*` сообщений).

Референс компоновки (квадрат, три зоны: header / middle graphic / footer banner) пользователь давал скрином рекламы «AI Role-playing games» — **только layout**, не стиль parchment.

## История подходов (что пробовали и отвергли)

### Итерация 1 — текстовая карточка + список URL

- Matplotlib-карточка без графика, ссылки текстом.
- **Отвергнуто:** нужны страна + scatter; вместо ссылок — QR; только URL главной.

### Итерация 2 — «Подготовить» + «Скачать»

- Двухшаговый UX из‑за тяжёлой генерации (SQL + seaborn).
- **Отвергнуто:** не нужен второй экран/шаг; одна кнопка должна сразу скачивать.

### Итерация 3 — текущая (лучше, но не готово)

- Одна кнопка `st.download_button`.
- Квадрат ~1080×1080, transparent, plot/histograms + QR + тексты из JSON.
- `st.cache_data` на сборку PNG.
- MIME сначала `image/png`, потом `application/octet-stream` (попытка убрать «открытие картинки»).

**Осталось плохо (причина откладывания):**

1. **UX Streamlit:** после клика «скачать» **пропадают графики и часть текста** — экран как будто «ломается» / выглядит как другая страница. Пользователь должен остаться любоваться графиками, файл просто падает в Downloads.
2. **Качество картинки:** много пустого пространства, текст накладывается на изображение, в целом **не выглядит как пост для соцсетей**.

Смена MIME **не помогла** с пропаданием графиков — это не (только) браузерное открытие PNG.

## Корневые сложности (важно для следующего агента)

### 1. Streamlit + download_button → rerun и одноразовые флаги отрисовки

В `ui/streamlit_app.py` графики на экранах результатов рисуются **один раз** под флагами:

- `country_plot_logged` — scatter + профиль страны
- `own_place_charts_logged` — гистограммы

Логика вида: «если ещё не logged → нарисовать plotly → выставить flag = True».

Любой клик по виджету (включая `st.download_button`) вызывает **полный rerun**. На следующем прогоне flag уже True → блок с `st.plotly_chart` **не выполняется** → графики исчезают. Текст результата (`last_text`) остаётся, кнопки меню — тоже; визуально «пропала середина».

**Направление фикса (не сделано):**

- Хранить готовые фигуры/HTML/PNG графиков в `session_state` и **перерисовывать на каждом rerun**, а флаг использовать только для одноразового **логирования** (`country_plot_loaded`), не для отрисовки.
- Или кэшировать plotly figure в state и всегда `st.plotly_chart(state["country_fig"])`.
- Не путать «залогировали просмотр» с «можно больше не рисовать».

Аналогичная ловушка уже была с `share_png_*` в session_state при уходе с экрана — чистили cache keys при смене screen.

### 2. Тяжёлая генерация PNG на клик

`build_country_share_png` снова зовёт `build_country_plot` (SQL + seaborn). На первом клике страница может «зависнуть»; кэш `@st.cache_data` помогает со 2-го раза, но не с UX первого скачивания и не с пропажей графиков.

Идеи на потом: пререндер PNG в фоне после показа результата; reuse уже построенного country_df/fig с экрана; уменьшать dpi.

### 3. Вёрстка matplotlib «как соцсеть»

GridSpec/абсолютные `add_axes` дали пустоты и наложення текста. Референс — плотная вертикальная иерархия без больших полей.

Возможные пути:

- Pillow-композиция: отдельные слои (title, plot crop, QR, text block, footer) с явными отступами в px.
- Фиксированный canvas 1080×1080 без `bbox_inches="tight"` (tight меняет размер и «разъезжает» layout).
- Не вкладывать полный seaborn-layout «как есть» — обрезать/перерисовать компактный scatter под карточку.
- Шрифты: системные/явные TTF; сейчас дефолт matplotlib выглядит «не для соцсетей».

### 4. QR без зависимости `qrcode`

`ui/mini_qr.py` — самописный QR (ECC-M, v1–10). Сделано из‑за недоступности pip/`python3-qrcode` в среде агента. Для продакшена предпочтительнее пакет `qrcode` + Pillow (проверить декод телефоном!). Самописный QR структурно тестировали, но **не верифицировали** zbar/pyzbar в CI.

### 5. Отвергнутые продуктовые идеи (не возвращать без спроса)

- Отдельная «страница результата» / share-link / Web Share API (на desktop Chromium часто недоступен).
- Двухшаговое «Подготовить» → «Скачать».
- Список URL на картинке вместо QR.
- Непрозрачный тёмный фон карточки (итерация 1–2) — пользователь просил прозрачный.

## Критерии приёмки при возврате к задаче

- [ ] Клик «Скачать…» **не убирает** plotly-графики и профиль/сравнение на том же screen.
- [ ] Файл появляется в Downloads; пользователь остаётся на экране результата.
- [ ] Логируется `load_image` с `type=country|place` (один раз на успешный клик скачивания).
- [ ] PNG квадрат, прозрачный фон, layout как в таблице выше.
- [ ] Нет наложений текста на график; мало пустоты; визуально «хочется запостить».
- [ ] Тексты только через `dialog_messages.json` (+ reuse profile/own_place).
- [ ] Тесты на сборку PNG + лог; ручная проверка QR телефоном.
- [ ] Явное ОКО пользователя перед merge в `main`.
